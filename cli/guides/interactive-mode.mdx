---
title: Interactive mode (TUI)
description: Manage IronBee from a full-screen terminal UI instead of individual commands.
---

`ironbee tui` opens a full-screen interactive terminal UI, a single place to browse your projects, toggle platforms, edit config, inspect sessions, and read code reviews without remembering individual commands.

It mirrors the CLI: anything you do in the TUI runs the same underlying logic as the matching command.

## Launch

```bash
ironbee tui
```

This opens the home menu. You can also jump straight into a specific area:

```bash
ironbee tui platforms
ironbee tui projects -p /path/to/project
```

| Argument / flag | Description |
|-----------------|-------------|
| `[area]` | Open directly into an area: `config`, `platforms`, `projects`, `sessions`, `scenarios`, `queue`, or `review` |
| `-p <dir>` | Start with a specific project as the active one (default: current directory) |

<Note>
  The TUI needs an interactive terminal. In a non-interactive context (CI, piped output) it exits with a hint to use the equivalent `ironbee config` commands instead.
</Note>

## Areas

| Area | What you can do |
|------|-----------------|
| **Configuration** | Browse and edit config keys across the global, project, and local layers, and the repository's [personal file](/cli/configuration/configuration#the-personal-file); see the effective merged value and where it comes from |
| **Platforms** | Toggle the browser, Node, Python, backend, Android, and terminal cycles per layer - or press **`s`** to have a detected client suggest the set and apply it |
| **Projects** | Install, uninstall, register, or unregister for the current directory or any project in your inventory; switch which project is active |
| **Sessions** | Browse sessions with their phase, verdict, and retry counts; run a read-only verdict check |
| **Scenarios** | Browse [saved verification scenarios](/cli/guides/scenarios) with their freshness (fresh / stale / unknown vs the current code, plus a `(N draft)` marker for never-replayed step caches). The detail pane lists each `llm-action` step cache - state, baseline commit, live-validated / draft, covered paths. Read-only - repair is the agent's `/ironbee-sync-scenario` |
| **Queue** | Inspect and drain the background job queue; manage dead-letter entries |
| **Review** | Read your [code reviews](/cli/guides/code-review): this worktree's first, then the other worktrees'. Each finding shows the reviewed code, the explanation, and the suggested fix, which you can apply to the working tree |

<Note>
  Installing from the **Projects** area runs the same flow as the CLI: a client picker when more than one is detected, then a **mode single-select** (`enforce` / `assist` / `monitor` - the equivalent of `ironbee install --mode`; picking `enforce` adds the same [strictness](/cli/guides/verification#strict-mode) and [fix-enforcement](/cli/guides/verification#fix-enforcement-block-on-a-fail-or-just-report-it) sub-pickers, with Esc stepping back) and, unless you pick `monitor`, a **platform multi-select** (pre-checked from the project's current config - the equivalent of `ironbee install --platforms`) to choose which cycles to enable, including the same **`s` suggest** key. One difference: a TUI install never runs the [devtools prefetch](/cli/guides/managing-projects#devtools-prefetch-warming-the-first-mcp-start) - it tips you to run `ironbee devtools prefetch` in a terminal instead.
</Note>

## Navigating

| Key | Action |
|-----|--------|
| `↑` / `↓` (or `j` / `k`) | Move within a list |
| `Enter` | Select / open |
| `Esc` | Back to the home menu |
| `q` / `Ctrl-C` | Quit |

### Keys by area

| Area | Keys |
|------|------|
| **Configuration** | `e` / `g` / `l` edit the project, global or local value; `P` edits the repository's personal file, for the remote the branch is pushed to (for another remote, use `ironbee config set --personal --remote <name>`); `x` unsets it from the global, project or local layer (you pick); `/` searches the keys. Credentials and the code review switches can't be edited in the project or local layer. To remove a value from the personal file, run `ironbee config unset --personal <key>` |
| **Platforms** | `e` / `g` / `l` toggle the cycle in the project, global or local layer; `x` clears it; `s` suggests a set |
| **Projects** | `Tab` switches between the current directory panel and the registered projects list. `i` install, `x` uninstall, `a` register, `d` unregister, `c` make active; `I` installs in every registered project and `X` uninstalls from all of them |
| **Sessions** | `v` runs a read-only verdict check |
| **Scenarios** | `r` refreshes |
| **Queue** | `d` drain, `D` drain all, `l` dead-letter entries (pick one to retry), `s` dead-letter stats, `c` clear the dead-letter, `p` purge |
| **Review** | `a` apply the fix, `e` open the file in your editor, `c` copy the finding, `S` the whole summary, `g` group by file or severity, `f` step the minimum severity, `/` filter, `l` hide or show the listed findings, `n` / `p` next or previous finding, `b` back to the list. See [The Review area](/cli/guides/code-review#the-review-area) |
| **Home** | `u` updates the CLI |

The breadcrumb at the top always shows the **active project**. In the Projects area you can switch which project is active, and every project-scoped area (Configuration, Platforms, Sessions, Scenarios, Queue, Review) retargets to it, so you can launch in one repo and inspect or edit another without changing directories.
