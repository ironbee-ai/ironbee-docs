When you run `ironbee install` in a project where [Claude Code](https://docs.anthropic.com/en/docs/claude-code) is detected, IronBee writes everything Claude needs to verify your agent's work. This page covers what gets installed and the agent-facing commands.

---

## What gets installed

| File | What it does |
|------|--------------|
| `.claude/settings.json` | Registers IronBee's hooks and the permissions the agent needs |
| `.claude/skills/ironbee-verification.md` | The verification skill the agent follows |
| `.claude/rules/ironbee-verification.md` | The verification rule that enforces the gate |
| `.claude/commands/ironbee-verify.md` | The `/ironbee-verify` slash command |
| `.mcp.json` | The devtools MCP servers — one entry per enabled cycle (`browser-devtools`, `node-devtools`, `backend-devtools`) |

These are merged into your existing Claude settings, not overwritten.

<Info>
  Restart Claude Code after installing so it picks up the new hooks, commands, and MCP servers.
</Info>

---

## Slash commands

IronBee installs the `/ironbee-verify` slash command, which the agent (or you) can invoke directly in Claude Code:

### ironbee-verify

Run a verification cycle for the current changes. By default it does a **focused** check, verifying only the areas affected by what changed. Variants narrow or widen the scope:

| Command | Scope |
|---------|-------|
| `/ironbee-verify` | Focused, verify the areas affected by the change (the default) |
| `/ironbee-verify full` | Everything full checklist regardless of what changed |
| `/ironbee-verify visual` | Visual only appearance, layout, theming |
| `/ironbee-verify functional` | Functional only behavior, interactions, data flow |

## How verification is enforced

IronBee installs a **Stop hook** that fires when the agent tries to finish a task. If code files changed, the hook runs verification automatically (the equivalent of `/ironbee-verify`) and blocks completion until every active cycle passes. The agent navigates pages, exercises the affected paths, and submits a verdict; on failure it fixes the issues and re-verifies, up to your [`maxRetries`](/cli/configuration/configuration#core-options) limit.

## Permissions

The permissions IronBee writes are scoped to what's actually active. Each enabled cycle grants its devtools tools (for example `mcp__browser-devtools__*` when the browser cycle is on), plus `Bash(ironbee *)` for the agent's CLI calls. Disabling a cycle strips its permission; switching to [monitoring-only mode](/cli/guides/verification#verification-modes) removes all IronBee permissions entirely. [Assist mode](/cli/guides/verification#switching-to-assist-mode) keeps the permissions and MCP servers (so manual verification still works) but drops the always-on skill and rule.

## Claude OAuth access

IronBee can read your Claude Code OAuth token (macOS Keychain or `~/.claude/.credentials.json`) to fill in statusline rate-limits for plans whose statusline JSON omits them, namely **team and enterprise**. It's **on by default** and Claude-only.

```bash
ironbee claude oauth-access status    # capability flag, token readability + expiry, live plan / rate-limit probe
ironbee claude oauth-access disable   # stop reading the token
ironbee claude oauth-access enable    # re-enable (and prime the macOS Keychain permission)
```

On macOS, `enable` reads the token right away so the Keychain permission prompt appears in your terminal. Choose **Always Allow** so later background reads don't re-prompt. Writes to the global config by default; `--project` / `--local` target other layers. Underlying keys: [`claude.oauthAccess.*`](/cli/configuration/configuration#claude-oauth-access-claude-code-only).

## OTEL collector

To derive context-usage metrics, IronBee runs a small **local OTEL collector daemon** that receives Claude Code's OTLP export and turns it into `session_context` events. One daemon serves every session on the machine, and it starts and reaps itself automatically, so you rarely touch it. When you need to:

```bash
ironbee claude otel status   # query the daemon's /health
ironbee claude otel stop     # graceful shutdown
ironbee claude otel retry    # re-process bodies that piled up during an outage (starts the daemon if needed)
ironbee claude otel run      # run in the foreground (mainly an internal spawn target)
```

All accept `--port` (default `15986`) and `-p, --project`. Tuning lives under [`otel.*`](/cli/configuration/configuration#otel-collector).
