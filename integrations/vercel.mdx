The Vercel integration verifies your preview deployments. Every preview deployment of an enabled project gets an **IronBee Verification** check. A cloud agent reads what the commit changed, exercises the preview against your real backend, and reports the verdict on the deployment. The evidence behind it is in the IronBee Console.

There is no workflow file to add and no test suite to maintain. Nothing waits on IronBee: the deployment completes as before, and the check reports on it.

---

## Prerequisites

- A Vercel **team** that builds preview deployments from a Git repository. Personal Vercel accounts can't install the integration.
- The **owner** or **admin** role on your IronBee account.
- The [IronBee GitHub App](/integrations/github). It's what lets the run check out a private repository and find the pull request behind a deployment. It's recommended for every repository and required for private ones.

---

## Step 1: Install and connect the integration

In the console, open **Integrations** in the sidebar, select **Vercel**, and click **Install the Vercel integration**. During onboarding, the same step is **Connect Vercel**. You can also start on Vercel: open the [IronBee integration on the Vercel Marketplace](https://vercel.com/marketplace/ironbee) and click **Connect Account**.

<img className="ib-shot" src="/images/integrations/vercel-marketplace.png" alt="The IronBee integration on the Vercel Marketplace, with the Connect Account button" />

1. On Vercel, choose the **team** and the **projects** the integration can see: all projects on the team, or a selected set.
2. Vercel sends you back to **Connect Vercel to IronBee**. Check the **Vercel team** and **Projects**, pick the **IronBee account**, and click **Connect**.
3. **Vercel connected** opens the project list so you can enable projects right away. See the next step.
4. When you close the list, IronBee takes you back to Vercel to complete the installation there. If it doesn't, click **Finish on Vercel**.

<img className="ib-shot ib-shot-light" src="/images/console/integrations/vercel-connect-light.png" alt="Connect Vercel to IronBee, showing the Vercel team, its projects, the IronBee account picker and the Connect button" />
<img className="ib-shot ib-shot-dark" src="/images/console/integrations/vercel-connect-dark.png" alt="Connect Vercel to IronBee, showing the Vercel team, its projects, the IronBee account picker and the Connect button" />

<Note>
  Only accounts where you hold the **owner** or **admin** role appear in the picker. If the page says the installation is no longer pending, it expired or was already completed. Open your Vercel team, go to the IronBee integration and install it again.
</Note>

## Step 2: Enable projects

A deployment starts a run only once its project is enabled. Until then, the Integrations page shows **Nothing enabled: deployments start no runs**.

1. The list is titled **Projects in** and your team's name. Every new project starts selected: clear the ones you don't want verified, or use **Select all** and **Select none**.
2. Set each one's verification type, or set them all at once under **Verification type**:
   - **Web** opens the deployment in a browser and exercises it as a user would.
   - **API** calls the deployment over HTTP and checks the responses against its contract.
3. Click **Create N projects**.

<img className="ib-shot ib-shot-light" src="/images/console/integrations/vercel-enable-projects-light.png" alt="Projects in Acme Web: five Vercel projects selected, each with a Web or API choice, the Verification type bar and the Create 5 projects button" />
<img className="ib-shot ib-shot-dark" src="/images/console/integrations/vercel-enable-projects-dark.png" alt="Projects in Acme Web: five Vercel projects selected, each with a Web or API choice, the Verification type bar and the Create 5 projects button" />

You can enable more projects later: from **Integrations > Vercel**, expand the installation, open the actions menu (the three dots) next to a project and choose **Enable**. Or open **Projects** and click **New project**.

## Step 3: Install the GitHub App

The Vercel integration knows the deployment; the GitHub App knows the code behind it. With both, the run verifies the pull request's changes, and the result also lands on the pull request as a check and a comment.

In **Integrations**, select **GitHub** and click **Install the GitHub App**. Then follow [GitHub App](/integrations/github).

## Preview access

Preview deployments are usually behind Vercel Deployment Protection, so IronBee can't open them. Pick one of the two options below. If your previews are public, skip this step.

<Tabs>
  <Tab title="Bypass token">
    The recommended option: previews stay protected, and runs send the secret when they open them.

    1. In the Vercel project, open **Settings > Deployment Protection > Protection Bypass for Automation** and add a secret. Copy it.
    2. In the IronBee Console, open the project and go to **Settings > Secrets**.
    3. Click **New secret** and choose the **Bypass token** tab.
    4. Paste the secret. The name defaults to `vercel-bypass`. Under **Applies to**, keep all environments, or choose the `preview` environment.
    5. Save the secret.

    <img src="/images/console/integrations/vercel-bypass.png" alt="Vercel: Protection Bypass for Automation" className="ib-shot" />

    Runs send the value as the `x-vercel-protection-bypass` header. IronBee never shows the value again. To change it, replace the secret's value.

    Add a bypass token to each Vercel project that has protected previews.
  </Tab>

  <Tab title="Turn protection off">
    1. In the Vercel project, open **Settings > Deployment Protection**.
    2. Turn off **Require Log In** under **Vercel Authentication** and save.

    <img src="/images/console/integrations/vercel-required.png" alt="Vercel: Deployment Protection, Vercel Authentication" className="ib-shot" />

    Previews become public: anyone with the link can open them.
  </Tab>
</Tabs>

## How it runs

<Steps>
  <Step title="The preview deploys">
    Vercel builds exactly as before. For every enabled project, IronBee keeps one check per verification type:
    - **IronBee Verification** for Web, **IronBee Verification · API** for API
    - scoped to preview deployments, non-blocking, and re-requestable
  </Step>
  <Step title="The check appears">
    **IronBee Verification** shows up under **Deployment Checks** on the deployment page, with its own status and duration.
  </Step>
  <Step title="The change is verified">
    IronBee starts a verification run with the deployment URL and its Git metadata.
    - **The changeset:** with the GitHub App, the run finds the pull request behind the deployed commit and works from its full diff. On a push straight to a branch, it compares against the commit's parent.
    - **The environment:** the run is against the project's `preview` environment, which IronBee creates on the first deployment. Its variables and secrets apply.
    - **Web projects:** the agent exercises the changed behavior in a real browser.
    - **API projects:** the agent calls the endpoints and checks the responses.
  </Step>
  <Step title="The result comes back">
    The verdict is written onto the check, with the summary and any issues, and a link to the run in the console. With the GitHub App installed, the same result also lands on the pull request.
  </Step>
</Steps>

## What you see on the deployment

The check moves through three states on the Vercel deployment page:

| State | What it means |
|-------|---------------|
| Queued | The preview is ready. The check is waiting for its run to start |
| Running | IronBee is verifying the preview. The duration counts up, and the link opens the run live |
| Concluded | The verdict, with the evidence behind it in the console |

The conclusion Vercel shows maps to the result like this:

| Result | Vercel conclusion |
|--------|-------------------|
| Pass | Succeeded |
| Fail | Failed |
| Not applicable | Neutral |
| The run couldn't complete | Neutral |
| Cancelled | Canceled |

When IronBee doesn't start a run for a deployment, the check is **Canceled** with no output. The GitHub check, when the App is installed, gives the reason.

The check's link opens the run in the console. While a Web run is going, you can watch it live: every action as it executes, the browser view and the network requests. Afterwards, the recording replays with the actions, network requests, traces and logs synced to it. API runs show the requests and responses, without a browser view. In the project's **Verifications** list, these runs carry the **Vercel** trigger. See [Verification detail](/console/verification-detail).

## Scope

- **Preview deployments only.** Production deployments aren't verified.
- **Enabled projects only.** Deployments of projects that aren't enabled, are archived, or are outside the installation's scope are ignored.
- **Non-blocking.** The check never holds up a deployment or a promotion.
- **Re-requestable.** Re-request **IronBee Verification** from the Vercel deployment page to start a new run.

## Managing the installation

**Integrations > Vercel** lists every connected installation with its **Team**, **Enabled projects**, **Status** and when it was **Connected**. **Manage on Vercel** opens Vercel's integrations dashboard. To add or remove projects, click **Manage access in Vercel** and use Vercel's **Manage Access**.

Expand an installation to manage its projects. Each project's actions menu (the three dots) holds:
- **Enable** turns on verification for a project.
- **Edit type** changes the verification type. The change takes effect on the next deployment.
- **Disable** stops verification. The project keeps its history, and runs from the CLI or the API still report to it.

The gear icon next to an enabled project, **Project settings**, opens the project's settings.

When a project leaves the installation's scope, or you uninstall the integration on Vercel, its IronBee project becomes **Not active**. It keeps its history and settings, and **Enable again** in the **New project** dialog brings it back.

<Warning>
  Installing the integration again from the Vercel Marketplace replaces the current installation and disconnects its projects.
</Warning>

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| No **IronBee Verification** check on the deployment | The project isn't enabled, the deployment is a production build, or the project is outside the installation's scope. Check the project list under **Integrations > Vercel** |
| The check concludes quickly, and the run shows the agent couldn't open the app | Preview access is missing. See [Preview access](#preview-access) |
| Neutral, "IronBee could not complete this verification" | The repository is private and the GitHub App doesn't cover it, or the run hit an error. Check the GitHub App, then re-request the check |
| The run verifies broad behavior instead of what the commit changed | The repository isn't on GitHub, or no pull request was found for the commit. See [GitHub App](/integrations/github) |
| "This install link is incomplete" during installation | The integration was installed on a personal Vercel account. Install it again on a team |
| The connect page says the installation is no longer pending | It expired or was already completed. Install the integration again from your Vercel team |
